# kakeibo2

個人用の家計簿アプリ(PWA)。HTML / CSS / JavaScript だけで動き、GitHub Pages で公開します。データは端末(localStorage)に保存し、ログインすると Supabase にも同期します。

## 機能

いちばんの目的は「今月あといくら使えるか」をはっきりさせることです。見た目・操作は、いま使っている家計簿アプリ(ミント色のヘッダー、行形式の入力画面、カテゴリーのアイコン、日別明細つきカレンダー)を踏襲しています。

- **ホーム**:今月あと使えるお金を大きく表示。ペース判定(順調/使いすぎ注意/予算オーバー)と予算の内訳
- **入力(支出)**:日付(矢印で1日ずつ、日付を押すとカレンダーから選べる)・メモ・金額・支払方法・カテゴリー(食費/日用品/美容/交際費/固定費/その他。右上の鉛筆で編集)
- **金額の上限**:1回の入出金は 999,999円(6桁)まで。時給×時間の合計が超えるときは保存しない
- **貯蓄**:収入のカテゴリー「貯蓄」で記録した分(B銀行への入金など)は使えるお金に入れず、貯蓄の合計に足す
- **入力(収入)**:カテゴリー(給与/交通費/臨時収入/その他/貯蓄)。「交通費」はよく使う金額(初期値 1,372/1,116円。メニューで変更)をボタンで選べる。「給与」のときだけ「時給×時間」と「金額」を切り替え(ほかのカテゴリーは金額だけ)。時給ごと(初期値 1,830/1,530/1,380/1,280円)に「○時間○分」を入れると合計が収入になる。時給ごとの金額は1円単位に四捨五入
- **支払方法と引落日**:現金/PayPay/JALカード/三井住友NL。PayPay などのコード決済は使った日に支払ったものとして扱う。口座からのチャージは「お金の移動」として記録し、あと使えるお金は減らさずに残高だけを増やす。カードごとの締め日・支払月(当月/翌月/翌々月)・支払日から引落日を計算し、土日祝・年末年始(12/31〜1/3)は翌営業日に調整
- **支払手段の提案**:入力画面で、支払いを最も先にできるカードに「おすすめ」を表示。上限超過や次の収入前の引落は優先度を下げ、使えるお金を超える支出は現金を提案
- **カレンダー**:日別の収入(青)・支出(赤)、カード引落のマーク、日付ごとの明細、検索
- **レポート**:使えるお金の内訳、貯蓄の合計、カテゴリー別・支払方法別の支出、引落・入金予定
- **同期**:メニューからログインすると、変更のたびにサーバー(Supabase)へ保存。開いたとき・アプリに戻ったときにサーバーの変更を取り込む。オフラインでも使え、つながったときに同期
- **メニュー**:同期(ログイン)、時給、カード、毎月決まった額の収入(固定給がある場合のみ)、最低限残しておく額、貯蓄の残高、カテゴリー、データの書き出し・読み込み

### 使えるお金の計算

```
あと使えるお金 = 先月からの繰越 + 今月の収入 − 今月の支出 − 最低限残しておく額
先月からの繰越 = 最初の記録の月から先月までの(収入 − 支出)の合計
ペース = 予算(繰越 + 収入 − 残しておく額)× 今日までの日数 ÷ 月の日数 と、使った額の比較
```

使い始めは、その日の手元のお金(メイン口座 + PayPay + 財布の現金。貯蓄用の口座は入れない)を収入の「その他」で、まだ引き落とされていないカード代を支出(支払方法は現金)で1件ずつ記録します。

カード払いを「使った月」と「引き落とされる月」のどちらで支出に数えるかはメニューで選べます(初期値は使った月)。

## Supabase(同期)の設定

1. Supabase でプロジェクトを作る(Data API はオン、「Automatically expose new tables」はオフ、「Enable automatic RLS」はオン)
2. SQL Editor で [`supabase/schema.sql`](supabase/schema.sql) を実行する(何度実行しても安全。実行前に「destructive operations」の注意が出るが、消すのは鍵のルールの入れ直しだけでデータは消さない)
3. Authentication → Users で自分のアカウントを作り(Auto Confirm)、新規登録(Allow new users to sign up)をオフにする
4. [`js/config.js`](js/config.js) に Project URL と Publishable key(または anon key)を書く。**Secret key / service_role key は書かない**

`js/config.js` が空のあいだは、同期なしで端末だけに保存します。

## GitHub Pages で公開する

1. このリポジトリの **Settings → Pages** を開く
2. **Source** を「Deploy from a branch」、**Branch** を公開したいブランチ(例:`main`)の `/ (root)` にして保存
3. 数分後に `https://<ユーザー名>.github.io/kakeibo2/` で開けます
4. スマホで開き、「ホーム画面に追加」するとアプリとして使えます(オフラインでも動作)

アプリを更新したときは `sw.js` の `CACHE` のバージョン(`kakeibo2-v1` など)を上げると、端末側のキャッシュが新しくなります。

## 開発

```sh
python3 -m http.server 8000   # http://localhost:8000 で確認
node --test tests/*.test.js   # 計算ロジックのテスト
```

| ファイル | 内容 |
| --- | --- |
| `index.html` | 画面の骨組み |
| `css/style.css` | スタイル |
| `js/icons.js` | カテゴリーと画面操作の線画アイコン |
| `js/logic.js` | 締め日・引落日・祝日・使えるお金・支払提案・時給・残高の計算(DOM 非依存) |
| `js/app.js` | 画面の描画と操作、データ保存 |
| `js/sync.js` | Supabase へのログインと同期 |
| `js/config.js` | Supabase の接続先(公開してよい値だけ) |
| `supabase/schema.sql` | Supabase に作るテーブルと鍵(RLS) |
| `sw.js` / `manifest.webmanifest` | PWA(オフライン対応・ホーム画面追加) |
